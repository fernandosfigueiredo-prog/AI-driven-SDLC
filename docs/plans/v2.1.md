## Decisões

| # | Decisão | Por quê | Alternativa descartada |

| D1 | Implementar no repositório do framework, não no projeto onde a sessão começou | o pedido proíbe instalar no produto ainda e o framework tem repositório próprio | evoluir a cópia do harness dentro de um produto |
| D2 | EM Buddy via hook `SessionStart` | exercitado de ponta a ponta nas simulações; reinjeta contrato e estado após resume, `/clear` e compactação; um único caminho. | D3 | Discovery como skill na conversa principal | entrevista em vários turnos no painel; transcrições de subagente são somente leitura | subagente de Discovery |
| D4 | Skills incluem os fluxos com `` !`cat` `` e concedem `Read(${CLAUDE_PLUGIN_ROOT}/**)` | uma fonte por regra e carregamento garantido; a inclusão só lê diretórios permitidos (descoberto nas simulações) | copiar o texto dos fluxos para as skills |
| D5 | Comandos com prefixo `/ai-driven-sdlc:` | `/plan` e `/status` são nativos nesta build | renomear os comandos |
| D6 | Skills da conversa principal não fixam modelo nem esforço | o cache de prompt é por modelo e esforço; trocar no meio relê o histórico sem cache | `model:` por skill |
| D7 | Roteamento por subagente com `model` do resolvedor; tier `max` (fable) só por opt-in | economia real sem perder cache; não presumir modelo que a conta pode não ter | fixar modelos por papel |
| D8 | Tag `[BLOQUEADO]` substitui `[CRÍTICO]` | o pedido define três estados; um vocabulário só | manter quatro tags |
| D9 | `.sdlc/state.md` é retrato reescrito; histórico no git/PR/Issues | o log que só crescia (dezenas de blocos) aumentava a carga cognitiva | handoff append-only |
| D10 | Limite observável no plano, dentro da aprovação da spec; L3 aprova o plano | execução autônoma após a aprovação, sem parada por tarefa | aprovação de orçamento por tarefa |
| D11 | Maturidade POC/MVP/Produção independente do risco | o review não pode exigir infraestrutura de produção de uma POC | maturidade embutida no nível |
| D12 | Repositório é plugin e marketplace (`source: ./`) | uma instalação, contratos acessíveis em `${CLAUDE_PLUGIN_ROOT}` | plugin em subpasta sem acesso ao `harness/` |
| D13 | Subagentes recebem contratos como texto no prompt | não herdam a concessão de leitura da skill | passar caminhos da pasta do plugin |
| D14 | Cada etapa carrega a sua skill (`ai-driven-sdlc:plan`, `ai-driven-sdlc:build`, `ai-driven-sdlc:review`, `ai-driven-sdlc:report`) | nas simulações, o refinamento feito "de memória" deixava as tarefas sem os campos do template | confiar que o agente lembre do procedimento |
| D15 | Tarefa pequena fica inline mesmo quando um tier menor bastaria | o subagente começa sem cache; numa tarefa pequena a carga de contexto supera a economia | sempre despachar para o tier mais barato |
| D16 | Handoff é um livro de registros append-only, um arquivo pequeno por registro, por épico (e um do projeto); o último registro é o estado atual, e o hook injeta só os 3 últimos. **Substitui a D9** (`.sdlc/state.md` reescrito) | a D9 trocou o log por um retrato para reduzir carga, mas perdia a memória do que aconteceu; ler só os últimos registros dá memória e leveza. Arquivo por registro evita conflito entre branches paralelas e torna "os últimos N" trivial. Obrigatório em todo trabalho: completo em L2/L3, uma linha em L0/L1 | um arquivo único por épico; manter state.md junto |
| D17 | Hierarquia épico → story → tarefa só quando há várias stories; stories refinadas perto da hora de construir; tarefas como checklist dentro da story (no GitHub: Issue do épico, uma por story) | feature pequena não ganha cerimônia; refinar tudo no começo envelhece; Issue por tarefa explode o número de itens | sempre três níveis; Issue por tarefa |

## Riscos e limites conhecidos

- **Interface gráfica:** a entrevista no painel e o formulário do AskUserQuestion só se validam com uma pessoa usando o VS Code (testes de aceitação 3 e 4).
- **API de plugins em evolução:** o comportamento foi verificado na 2.1.301; versões futuras podem mudar regras de permissão ou de inclusão. Os testes de contrato e as simulações detectam regressões.
- **Bash obrigatório no Windows** para o hook e as inclusões.
- **Gates por orientação:** aprovação de spec e orçamento são checados pelo agente, não bloqueados pelo runtime. As simulações medem a aderência.
- **Custo das simulações:** cada passo é uma sessão real; rodam por opt-in.
